# Verifier policy (UAB v0.1)

**Locus ladder.** a0 the performing system — never admissible. a1 the same process wearing a reviewer
persona — never admissible. a2 a separate process on a **copy** of the deliverables with no inherited
environment — the weakest admissible locus. a3 a separate host. a4 a separate party that holds the
ground truth and returns a scalar. a5 cryptographic promotion. One base model in two processes with
separate credentials and enforced write sets satisfies a2; one model told to now act as reviewer does
not.

**Criterion register.** Criteria are written before the work exists, refuse a criterion about an
existing deliverable, refuse a duplicate name, refuse a criterion that does not say what it misses,
and seal when execution starts. The register is hash-chained so an edit is detectable. It reports
`σ`, the share of criteria the system under test authored; the manifest bounds `σ`.

**Hidden / public split.** Public: the verifier's *type*, the specification, worked examples, the
reference implementation where one exists. Hidden: the scored instances or key. A hidden key is an
assertion until something tests it: parameterised families ship a **specification–key test**; fixed
items are **concordance-audited** when two executors fail identically.

**Versioning.** The verifier version is part of every result. A verifier change is a benchmark
version.

**Disagreement.** Where two admissible verifiers exist, disagreement is recorded as a rate, and an
item with verifier disagreement above 10 % is withdrawn from certification until audited.

**Graded where a boolean hides the signal.** Families with many sub-checks report a fraction and
separate failure modes: `specification`, `insufficient_search`, `crash`, `timeout`,
`not_attempted`.
